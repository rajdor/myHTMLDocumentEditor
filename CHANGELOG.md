# Changelog

## Unreleased
- App theme, in both programs: an App theme button at the top of the Help window sets how the editor's own controls look: the toolbar, its bars, menus, the notebook panel and its dialogs. The same themes as the diagram editor and Data Model Studio, plus Blueprint (Fine Line), the look the editor had before. Material Design unless chosen; kept in this browser. The document is never changed by it and keeps the Fine Line style. The diagram editor and Data Model Studio open in the same app theme, while each diagram and model keeps its own style.
- Diagrams, in both programs: latest myDiagramer (separate app theme and diagram style, a new diagram starts in Blueprint, shape and format panels can be hidden or slide in).
- Data models, in both programs: latest Data Model Studio. Guided mode is removed. A menu bar (File, Edit, View, Model, Help) above the toolbar, Phosphor icons with hover tips on the toolbar, the legend under Help, Cancel and Done at the right of the toolbar, a Screenshot view, and the file name with a dot shown only when there are unsaved changes. Select one or many (click, Shift or Ctrl click, drag a box), move, align, distribute, copy, cut, paste, duplicate and delete them, with undo and redo. Relationships can be clicked, moved by their bend points (double-click a bend to remove it) and deleted; dragging from an entity's link handle or an attribute to another entity makes a relationship. Notes can be added to the canvas. No more dimming of other entities on hover.
- Tests: t56 app theme; t15 expects the initials button in the app theme's accent.
- Data models, in both programs: Data Model Studio has an app theme (Material Design unless chosen, not kept when opened from a document) and a content theme for the model and its picture (Fine Line unless chosen, kept in the model). The theme menu has both, and its ticks follow the choice. A model opened from a document keeps its own content theme; the document's style only starts a new model in Fine Line.
- Diagrams, in both programs: an Entity card in the diagram editor's Containers (header band with a white title, outline in the header colour, a tinted body with text), kept in its colours in the Blueprint style (latest myDiagramer).
- Data models, in both programs: Data Model Studio has three card views on its toolbar, Details (attributes), Compact (a count of what each entity holds) and Conceptual (each entity's description, for business readers). Every view keeps the whole model; the model remembers the view it was left in, and Done places a picture of that view. Switching view alone counts as a change, so Done updates the picture. In Conceptual an entity with no description says so while editing, and the picture leaves that out.
- Tests: t55 data model views.
- Pictures made into diagrams, in both programs: a box whose text is set out in rows and columns (a data model entity: key, name and type on each row) becomes one table in its label, so each row stays a row, each column keeps its side (types to the right), and each piece keeps its own colour, size, bold and italic. A title in a header band stays in the band. Text that is not in rows and columns converts line by line as before.
- Diagrams: labels holding a table keep their column alignment, on the canvas and in the picture on the page (latest myDiagramer).
- Diagrams, in both programs: a picture or a Mermaid definition opened for editing says it was converted, in a bar across the top of the diagram editor: where it came from, that the layout and text formatting may differ, that the page is unchanged until Done (Cancel keeps the original), and how many shapes and lines were recognised. A diagram that already has its draw.io source opens with no bar. The diagram editor is the latest myDiagramer.
- Data models, in both programs: a new Data model button in Insert, beside Diagram, opens Data Model Studio (myEntityModeller, carried in `vendor/data-model-studio.html`) in front of the document. Done places a picture of the visible tab with the whole model kept beside it (`<div class="dg dm" data-dms="...">`); double-click, or select and press Enter, to edit it again. It opens in its Blueprint theme, offers Guided and Fly solo but not Claude-assisted (the editor allows no network access), and is selected, copied, captioned and deleted like a diagram, with its own names on the bar (Data model, Edit data model, Delete data model). The picture carries every style on its own elements and no ids, classes or style block. While the table buttons show, Data model steps aside so the toolbar stays on one row at 1440 wide. Its scripts are allowed by hash like the diagram editor's.

H4 used to be 14px, semi-bold and in soft ink, which was smaller, lighter and paler than bold paragraph text (15px), so a bold line under an H4 outranked its heading. A saved page carries its own styles, so an existing page takes the new look when it is next opened and saved.

A dark colour gives the cell white text; links keep the browser's own blue. For the whole table: Spacing (none, small, medium), Padding (small, normal, large), Borders (grid, none) and Corners (square, rounded). Rounded turns Small spacing on, and no spacing turns Rounded off, as cells that touch cannot be round. In a table with spacing a cell with no text and no colour draws nothing on the saved page. A fancy table keeps its own spacing, borders and corners. Repeat last toolbar command and Inspect formatting cover all of it; a saved page prints the colours. Not available in a Markdown file.

- Cursor fix, in both programs: in a page that carries markup from another program (a span with no class, a style attribute), pressing Enter made the new line but left the cursor on the old one, and Enter on an empty line sent the cursor back to the text above. The clean-up that removes such markup as you type put the cursor back by counting characters, which cannot tell an empty line from the end of the line before it. The cursor is now kept by its block and its place in it, counting line breaks, so it stays on an empty line, at the start of a line and after a line break. Seen in boxes of a page not made in the editor, but it was not particular to boxes.
- Boxes: text in a box is always in paragraphs. Loose text in a box, and a plain div holding only text, as a page made elsewhere can have, become paragraphs when the page opens and as you edit, so Enter and the styles work there as anywhere else.

- Boxes: with text selected, the Box list puts the blocks the selection reaches into the new box, each one whole (a list or table is taken whole; a block the selection only touches the edge of is left out). With no selection it inserts an empty box as before. This brings back boxing a selection, which had been taken out.
- Show blocks: the three kinds of block now look unlike one another and unlike a table's own grid. A container is dashed amber with a light tint and its label; a table has a solid purple outline and a table tab; a paragraph, heading, list or code block has no outline, only a small grey tag in the left margin (p, h2, ul). Text blocks used to have a dotted grey outline that read as table cells.
- ID tags: a double-click on a tag, or on the word beside it, selects that one only. Where no space character lies between the two (the gap seen is the tag's own margin) the browser took both as one word.

- Tables: after Delete column the cursor stays in the table, in the same row, in the column that took the deleted one's place (or the column to its left when the last one on the right went), so columns can be deleted one after another. It used to leave no cursor, and the next table button said to place the cursor in a cell. Deleting the only column left, or the only body row left (so a 1 x 1 table too), deletes the table, as Word does, in one undo step; both used to refuse.

Ctrl+C now copies a selected diagram or picture wherever the keyboard focus and the pointer are; it used to work only when the cursor had been placed in the page before the diagram was clicked, and text selected elsewhere was copied instead. Ctrl+X cuts it (one undo step). A selected diagram is marked more clearly: a heavier outline, a tint around it and a tab saying what can be done; the text cursor goes while it is selected. The bar under the toolbar adds Copy and Cut, and says when it was copied.
- Notebook: favourites can be put in any order. Drag a favourite above or below another, use Move to top, Move up, Move down and Move to bottom on its right-click menu, or press Alt+Up and Alt+Down on a favourite with the focus. The order is saved in the notebook's settings. New favourites still go at the end.

Double-click one in the editor to convert it to a diagram-editor diagram, which fits the page width with no script.

Nothing of it is saved: the saved page holds no folds and no script, and a page always opens unfolded. Folding the section the cursor is in moves the cursor to the end of its heading; pressing Enter there, or editing into a folded section any other way, opens it. The browser's Find and an Index link open the sections above what they go to. Undo keeps the folds. Printing shows everything. Markdown files fold the same way.
