# Changelog

## Unreleased
- Smaller saved documents. The italic font and the code font go into a saved document only when the page uses them, read from how the browser has drawn it (italic text; code blocks, inline code, ID tags, Q&A labels). A page with neither drops from about 189 KB to about 92 KB and looks the same; a page with one of them is about 135 KB or 146 KB. The font comes back at the next save once the page uses it. In the notebook, history copies shrink the same way. Documents saved earlier pick this up the next time they are saved. Both programs.
- Tests run several at a time (one for each processor, at most 4), which roughly halves the time on two processors. A test that fails while others were running is run again on its own.
- Pasting cells into a table. A block of cells (part of a column, a row, a rectangle; copied here or in a spreadsheet) pasted with the cursor in a table now goes in cell for cell from the cursor's cell, across and down. Before, all of it went into the one cell. If cells in the way already hold something, or the table has fewer rows or columns than the block, a message says how many cells are replaced and how many rows or columns are left out, and asks first; Cancel pastes nothing. No rows or columns are added. One copied cell still goes in at the cursor as text, and a block pasted outside a table still makes a table. Both programs.
- Saved documents are plain ASCII. Any character outside it (dashes, arrows, curly quotes, accented letters, symbols) is written as its HTML code, by name where there is a common one (`&mdash;`, `&rarr;`) and by number otherwise. The document looks the same in a browser and in the editor, and re-opens exactly as it was. Before, a program that read a saved file with the wrong encoding showed these characters as garbage. Documents saved earlier pick this up the next time they are saved. Both programs.
- Notebook: history. A full copy of a page is kept in `.history/<page path>/`: the version being replaced, each time you save over one, and the unsaved work, every 5 minutes while the page has unsaved changes. A page left open and untouched writes nothing, and a copy history already holds is not kept twice. Right-click a page and choose Page history to see its copies and restore one; a restored copy is unsaved until you press Save. If the editor closed with unsaved work, opening the page offers to recover it. History follows a page or folder renamed or moved in the notebook.
- Notebook: a status line at the foot of the explorer shows the size of history and trash: grey under 50 MB of history, a note from 50 MB, a warning from 100 MB. The interval and both thresholds can be set in `.notebook/settings.json` (`historyMinutes`, `historyNoteMB`, `historyWarnMB`).
- Notebook: clean-up. Clicking the status line lists history by page with sizes and marks pages that no longer exist. Delete all but the newest copies of each page, copies older than a number of days, history of pages that no longer exist, or empty the trash. Each asks first and says how much it will remove.
- One project, two programs. `npm run build` now builds `fine-line-editor.html` (the document editor on its own) and `fine-line-notebook.html` (the same editor with the notebook explorer) from one source. Everything outside `src/notebook/` is shared; notebook code, styles, markup and the Markdown converter are in `src/notebook/` and go into the notebook only. The package is `fine-line`. Shared tests (`t*`) run against both programs and notebook tests (`nb*`) against the notebook; `t35-outputs` checks the editor carries no notebook code. Entries below that begin "Notebook" apply to `fine-line-notebook.html` only.
- Notebook: the explorer opens from a tab at the left edge of the window and closes from the arrows at the top of the panel. The toolbar is the same in both programs, so the notebook no longer needs room in it.
- Notebook: named Fine Line notebook, built as `fine-line-notebook.html`. Help and the browser tab show the name. The unsaved-draft copy kept by the browser now has its own key, so it is not shared with the Fine Line document editor. Saved pages keep the `fine-line-editor` format marker, so both programs open each other's pages.
- Notebook: Markdown (`.md`, `.markdown`) and plain text (`.txt`) files open as an import. Markdown is converted by marked 18.2.1, which is now built into the editor: headings (levels below H4 become H4), bold, italics, links, lists, task lists as checklists, tables and code blocks; front matter is dropped and its title used when the file has no H1. Text becomes one paragraph a line with the file name as the title. The result goes through the same cleaning as any opened document, is a new unsaved page, and saves as an HTML page beside the original, which is left as it is.
- Notebook (first part): a panel that shows a folder on disk as a notebook. Folders are sections and files are pages, to any depth; folders load when expanded. Click a page to open it; unsaved changes prompt Save and switch, Discard and switch or Cancel. A new page gets its file at first save, named after the first H1; a name already used prompts for another name or to replace. Right-click menu, rename in the row (checked on Enter, clashes refused, names compared ignoring case), new folder, move by drag, delete to a `.trash` folder that keeps the original path, restore, delete permanently, empty trash. Files the editor cannot open are greyed and open in a new browser tab. Hidden files can be shown or hidden; the choice is kept in `.notebook/settings.json`. Saving checks whether the file changed on disk, writes one file at a time and reads it back. The folder is remembered by the browser and reconnected with one click. Other HTML opens as an import. In browsers without folder access the tree is read-only, Save downloads, and a notice says Chrome or Edge works best. Still to come at that point: history, status bar and clean-up, favourites, sorting, search, templates, pasted images.
- Toolbar inserts go where the cursor is. A code block, table, box or diagram takes the place of an empty paragraph; with the cursor inside a paragraph or heading it goes before it (cursor at the start), after it (cursor at the end) or between its two halves. Before, it always went after the block, leaving an empty paragraph above it. In a list or table, which cannot hold these, it still goes after the list or table.
- Q&A button: it now works on the block the cursor is in, like the list buttons. A paragraph or heading becomes a question (each one, when several are selected) and the button again turns a question or answer back into a paragraph. Before, it added a new empty question after the block, a second list when pressed inside a Q&A list, and one at the end of the page with no cursor. It is dimmed in a list item, table cell or code block.
- Clear format keeps the selection, so the next toolbar choice (a style, bold, a list) applies to the same text. With the cursor only, it stays a cursor.
- Fixed: a line break typed beside an ID tag (Shift+Enter, or Enter in a table cell) went inside the tag, so the tag ran over two lines. The break now lands outside the tag.
- Fixed: Enter at the end of a list item or paragraph that ends with an ID tag started the next one inside a new tag. It now starts plain.
- Fixed: the ID tag button made no tag in a list item, and added stray styles to the tag elsewhere. With nothing selected the placeholder "ID" is now selected, ready to type over.
- Fixed: joining two blocks (Backspace at the start of one, Delete at the end of one, or deleting a selection across them) turned an ID tag at the start of the second into plain text, and left stray styles on tags and inline code that moved.
- Fixed: the list buttons on a paragraph with line breaks made a list from one line only, inside the paragraph. The whole paragraph now becomes one item with its line breaks kept; several selected paragraphs become one item each.
- Fixed: taking the list off an item left its text loose in the page, and in a box removed the box. The item now becomes a paragraph, line breaks kept.
- Fixed: Enter at the end of a line that has a line break after it started the new item or paragraph with a blank line.
- Start numbering at: a button beside the list buttons sets the first number of the numbered list the cursor is in, so a list can carry on from an earlier one after text, a table or a diagram between them. The form offers the number after the nearest numbered list above. The number is fixed once set and does not follow later changes to the earlier list. Saved as the list's own start number, so saved documents need no script. Lists pasted from other programs keep their start number.
- Bold is one set weight (700) in the editor and in saved documents. It was the browser's relative weight, which came out as 900 in a header cell or heading.
- Paste from other programs: bold that lands in a header cell, heading, Q&A question or box label is dropped, because those have their own weight, and bold inside bold becomes one bold. Bold in paragraphs, list items and body cells is kept. Bold copied in the editor is kept wherever it is pasted.
- Fixed: the list buttons broke a Q&A list (the answer or question lost its place in the list). An answer can now hold bullet, numbered and check lists, made from the line the cursor is on; the list buttons do nothing in a question.
- More formats: a toolbar list with superscript, subscript, strike-through and inline code, each switched on or off for the selected text; the list ticks the ones on at the cursor. Inline code now uses the code font. Pasted strike-through is kept.
- List indent and outdent: two buttons, and Tab and Shift+Tab in a list. Outdent at the top level turns the item into a paragraph (a plain line in a table cell). Q&A lists are unchanged.
- Link button opens a form with display text and address in place of the single address prompt. The display text defaults to the selected text; the address defaults to the selected text when it is a web address, or to a web address on the clipboard when the browser already allows reading it (it never asks).
- Toolbar: narrower Style and Box lists and tighter group spacing so it stays on one row at 1440px.
- Inspect formatting: a toolbar button (magnifying glass) opens a popup listing the formatting on the text at the cursor or the selected word, from the outside in, with how it looks (font, size, weight, colour). Anything the toolbar cannot make there is marked, and one format can be removed at a time. It reads the document only when the button is pressed.
- Paste from other programs: a heading inside a table cell or list item becomes a bold line (a plain line in a header cell), because the toolbar has no headings there. Superscript, subscript and inline code are still kept.
- Clear format is thorough: in a table cell or list item that also holds a list or a heading it now clears the loose text too, a heading or paragraph inside a cell becomes a plain line instead of a paragraph, and strike-through, inserted and deleted text, keyboard and sample text are removed with the rest. Links and ID tags stay.
- Compact list: a button beside the list buttons puts less space between the lines of the list the cursor is in (bulleted, numbered or checklist, inner lists included).
- Selecting cells: Shift+click on another cell of the same table, or a drag from one cell into another, selects the block of cells between them (a column, a row or a rectangle). Bold, Italic, Clear format, the header and merge buttons, Delete, copy and cut act on the block; a copied block is a table, and tab-separated text. Escape, a click or typing ends it.
- Column widths: drag the border between two columns to move width from one to the other; the table keeps its own width. Widths are saved as percentages and follow added and deleted columns. A double-click on a border goes back to automatic widths.
- Table headers: four table buttons set a whole row or column as a header or a sub header, and the same button again makes it ordinary. Any row can change, the top one included. Header cells are marked as heading a row or a column for screen readers. A new row is ordinary apart from its header columns, and a new column is ordinary apart from its header rows.
- Diagram editor updated: the points shown by Edit points are the points a line can attach to, and other shapes stay connectable while one shape's points are edited; a label added to a line starts with a background in the canvas colour instead of transparent.
- Third-party notices: `THIRD-PARTY-NOTICES.md` carries the copyright notices and licence texts for Phosphor Icons, the three fonts, Rough.js and the mxGraph routing code; the README has a Credits section.
- Fonts: body text is Instrument Sans and code blocks and ID tags are JetBrains Mono (ligatures off). Both are embedded in the editor and in every saved document, so a document looks the same on any computer; this adds about 137 KB to each saved file. Headings keep Architects Daughter.
- Boxes for the reader: the Box list beside the Style list inserts a Note, Information, Tip, Warning or Critical box after the current block, ready to type or paste into. What goes in keeps its own style. The label starts as the type's name and can be retyped. With the cursor in a box the list changes its type. Enter on an empty last line leaves the box; Remove box keeps the content. These are separate from margin notes, which are for the author and reviewers.
- The example document has a checklist and one box of each type.
- Checklist: a Checklist button beside the list buttons makes a list with tick boxes. A click ticks a box and the tick is saved with the document. Saved documents need no script: the boxes are real checkboxes, so a reader can still tick them, though those ticks are not kept.
- Paste into a table cell or list item no longer leaves out text that sits beside a block (or in a plain box) in the copied content.
- A new list is no longer left inside the paragraph it was made from, and the cursor keeps its place when a list is made.
- Toolbar: the row, column, merge and compact buttons appear only while the cursor is in a table, to the right of the two insert buttons; the Table group is now last so nothing else moves. Margin notes have their own Notes group. The Diagram button uses the shapes icon. Show Index Levels is one button that steps through 1, 2 and 3, with the current level shown on it. Buttons are narrower so the toolbar stays on one row.
